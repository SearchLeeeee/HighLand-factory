# Block：文档同步

> 类型：项目级通用约束 · 适用：所有会改变行为、契约或事实的变更

## 原则

代码与文档是同一变更的两面。行为变了而文档没变，等同于交付了错误信息。文档同步不是“以后再补”，而是完成定义的一部分。

## 必须同步的情形

- 对外或对内接口、数据结构、序列化格式、错误语义变化；
- 配置项、默认值、开关、环境要求变化；
- 权限、认证、数据归属或访问边界变化；
- 目录布局、入口、构建或运行方式变化；
- 新增、删除或重命名权威文档与文件；
- 约束块、manifest、profile 的组合关系变化；
- 修复了会导致他人误操作的高风险缺陷。

## 同步要求

1. 文档改动与代码改动放在同一变更内，不拆成“先合代码后补文档”。
2. 先更新约束与事实文档，再写实现；提交顺序按 [commit-granularity.md](commit-granularity.md) 执行。
3. 只维护一处权威表述；其他位置引用它，不复制正文。
4. 文档必须写清适用范围、生效条件与失效条件，避免“永远正确”的空话。
5. 文档中的示例必须可验证，且不得包含真实凭据或个人数据。
6. 删除行为时同步删除或标注过期文档，不能留下误导性旧说明。

## 禁止

- 用“代码即文档”作为不更新文档的理由。
- 把未验证的推测、计划或临时结论写成事实。
- 在稳定文档中记录任务状态、人员分工或一次性排查过程。
- 为了少改一处而让两份文档各说一套。

## 自检

- [ ] 受影响文档已列出并逐一确认。
- [ ] 文档中的路径、名称与行为与实现一致。
- [ ] 没有复制粘贴造成的重复权威。
- [ ] 过期内容已删除或明确标注。
