# Block：交接输出

> 类型：项目级通用约束 · 适用：阅读、实现、评审、验证四类交接

## 固定结构

所有交接文档必须按以下七段输出，顺序不变，标题不改；没有内容时写“无”，不得省略章节：

1. **角色与范围**：执行角色、所属 owner、任务边界、明确不做什么。
2. **输入与权威来源**：采信的文档与代码位置，以及被排除的来源及原因。
3. **已完成动作**：按时间顺序列出动作与结果，不写心路历程。
4. **证据**：测试、日志、截图、命令输出摘要或评审记录的可复现引用。
5. **未决问题、风险与假设**：区分“已确认事实”“待确认假设”“已知风险”。
6. **影响面与回滚**：影响的文件、契约、数据、权限、其他 owner；如何回滚。
7. **下一步与需要确认的事项**：建议动作、责任角色、需要人类决策的点。

## 写作规则

- 先结论后细节；读者不读完也能知道是否阻塞。
- 证据必须能被他人复现，不能只写“已验证”。
- 引用路径使用相对路径，不粘贴大段代码或完整日志。
- 不写真实凭据、个人数据或生产地址；必要处使用占位符并说明。
- 不把推测写成事实；不确定时标注“假设”与验证方式。
- 不隐藏失败：失败、跳过、未覆盖项必须显式列出。
- 交接不替代权威文档；需要改变契约时另走文档同步与评审流程。

## 角色附加要求

- 阅读交接：必须包含“范围 / 权威来源 / 事实与约束 / 风险与未决问题 / 实现入口”五节。
- 实现交接：必须说明改动清单、行为变化、验证方式、回滚方式与评审重点。
- 评审交接：按评审报告的固定章节输出，结论只能是“通过 / 有条件通过 / 不通过”。
- 验证交接：必须逐条对应验收项，给出证据与“通过 / 失败 / 未覆盖”。

## 自检

- [ ] 七段齐全，标题与顺序正确。
- [ ] 结论、证据、风险三者一致，没有互相矛盾。
- [ ] 未覆盖项与失败项没有被隐藏。
- [ ] 敏感信息已脱敏。
