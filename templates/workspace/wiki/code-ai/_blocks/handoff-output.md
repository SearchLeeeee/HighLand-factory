# Block：交接输出

> 类型：项目级通用约束 · 适用：阅读、实现、评审、验证四类交接

## 通用必需信息

交接必须覆盖以下信息；它们是内容要求，不要求在角色模板外再套一层标题。实现交接及没有专属模板的角色使用以下七段，顺序与标题保持一致；无适用内容写“无”：

1. **角色与范围**：执行角色、所属 owner、任务边界、明确不做什么。
2. **输入与权威来源**：采信的文档与代码位置，以及被排除的来源及原因。
3. **已完成动作**：先说明结果，再列出必要动作，不复制执行流水。
4. **证据**：测试、日志、截图、命令输出摘要或评审记录的可复现引用。
5. **未决问题、风险与假设**：区分“已确认事实”“待确认假设”“已知风险”。
6. **影响面与回滚**：影响的文件、契约、数据、权限、其他 owner；如何回滚。
7. **下一步与需要确认的事项**：建议动作、责任角色、需要人类决策的点。

## 写作规则

- 先结论后细节；读者不读完也能知道是否阻塞。
- 证据必须能被他人复现，不能只写“已验证”。
- 引用路径使用相对路径，不粘贴大段代码或完整日志。
- 不写真实凭据、个人数据或生产地址；必要处使用占位符并说明。
- 不把推测写成事实；不确定时标注“假设”与验证方式。
- 不隐藏失败：失败、跳过、未覆盖项必须显式列出。
- 交接不替代权威文档；需要改变契约时另走文档同步与评审流程。
- 在现有“输入与权威来源”和“证据”中引用当前对象、获批计划与本次差异，列明实际命令、退出结果、证据位置及复用条件；已读且未变的来源不重复摘抄。接手者只补查变化、缺口或会影响判断的来源。
- 存在可复用环境时，在现有“下一步与需要确认的事项”中交代资源入口、归属、清理责任和剩余必需检查；准备结果不等于验收通过。机器私有入口经忽略配置或当次交接传递，不写进提交材料。
- 准备细节按 `.factory/local.yaml` 的 `factory_root` 解析出的 `skills/hl-workflow-governance/references/execution-preparation.md` 执行。只传当前阶段所需增量，不把固定章节再包装成第二套交接或独立准备报告。

## 角色最终输出模板

- 阅读交接：只使用[四角色流程](../subagent-flow.md)的五节阅读模板；通用证据、影响及待决信息分别放入事实、风险和实现入口。
- 实现交接：使用上面的七段，说明改动清单、行为变化、验证、回滚和评审重点。
- 评审交接：只使用[评审报告契约](review-agent-contract.md)的固定模板；范围、证据、影响与后续事项填入对应章节。
- 验证交接：只使用[四角色流程](../subagent-flow.md)的五节验证模板，逐条对应验收项、证据及“通过 / 失败 / 未覆盖”。

角色模板覆盖上述通用信息即可，不要求重复章节、另补一份通用交接或为同一结果增加文档。

## 自检

- [ ] 使用一套适用的角色结构，通用必需信息已覆盖。
- [ ] 结论、证据、风险三者一致，没有互相矛盾。
- [ ] 未覆盖项与失败项没有被隐藏。
- [ ] 敏感信息已脱敏。
