# Block：夹具治理

> 类型：项目级通用约束 · 适用：测试夹具、样例数据、回放记录与假服务

## 来源与合规

1. 夹具必须是合成数据，或经过不可逆脱敏且获批的数据；不得使用真实客户数据、生产导出或未脱敏日志。
2. 不得包含真实凭据、令牌、私钥、个人标识或内网地址；需要时使用显式假值与保留域名。
3. 每个夹具都要说明来源、生成方式、责任人与适用范围；来源不明视为不可用。
4. 涉及第三方数据时，确认许可与使用边界，不把受限数据提交进仓库。

## 最小与可读

- 只保留证明行为所需的最小字段与记录数，便于审阅。
- 结构清晰、命名可读，避免大段二进制或不可解释的压缩包。
- 大文件优先由脚本按确定规则生成，而不是直接提交。
- 一个夹具只服务一个明确场景，避免“万能大样例”。

## 确定性与隔离

- 固定时间、随机种子、排序与标识，保证跨环境可复现。
- 夹具不得写入共享状态或依赖外部服务的实时数据。
- 使用假服务或回放时，要固定版本并记录契约来源。
- 测试结束后清理临时产物，不污染工作区。

## 版本与治理

- 夹具随契约变化更新；契约变更时检查夹具是否仍代表真实形状。
- 删除夹具前确认没有测试或文档引用。
- 过期、失真或不再合规的夹具要标注并替换，不能静默保留。
- 夹具变更按普通变更走评审；涉及脱敏或合规判断时必须评审。

## 自检

- [ ] 来源、生成方式与责任人已记录。
- [ ] 无真实凭据、个人数据或生产数据。
- [ ] 时间、随机与标识可控，结果可复现。
- [ ] 体量最小、结构可读、无无关文件。
- [ ] 契约变化后夹具已同步。
