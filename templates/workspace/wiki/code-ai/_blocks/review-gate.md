# Block：评审门

> 类型：项目级通用约束 · 适用：所有 owner 与 feature 工作

## 强制评审条件

出现以下任一情况，必须经过独立评审：

- 涉及安全、认证、授权、权限、密钥或敏感数据；
- 涉及数据写入、删除、迁移、回填或不可逆操作；
- 涉及真实资金、订单、支付、计费或外部副作用；
- 改变对外契约、公共接口、序列化格式或配置语义；
- 跨 owner、跨模块或跨仓库改动；
- 高风险缺陷修复、回滚、热修或紧急变更；
- 自动化测试不足以证明正确性；
- 项目规范另行规定的情形。

## 独立性

- 实现者不得担任自己工作的最终评审者。
- 评审者只依据输入包与证据判断，不依据实现者的口头保证。
- 评审者不得直接修改被评审对象；发现问题退回实现角色。
- 评审者与实现者存在利益或职责冲突时，升级给人类指定第三方。

## 评审前条件

至少需要：目标与验收标准、变更范围与基线、权威契约出处、测试与验证证据、风险与回滚、未决问题、必要授权。缺项先诊断影响，只暂停无法判断的部分。默认用 Git revision 加相关 diff / 新增文件内容识别对象，评审期间保持来源稳定；未授权提交仍可评审和验证可识别的未提交内容，不强制预提交、全树 clean、新 clone、逐文件摘要或额外 receipt。只有实际来源歧义、污染、并发冲突或制品完整性需要时，简短说明风险并增加必要的内容固定、隔离或摘要，不增加额外审批。

评审范围按实际改动及影响选择最小充分集合，复用未变化且仍适用的结果，同一事实不叠加等价校验。独立判断不默认重跑全部检查或重建环境；主编排核对关键证据并按实际风险抽查。

## 阻断规则

- Blocker：禁止合入，必须修复并重新评审。
- High：必须修复；或在 owner 书面接受风险、登记后续项与期限后，才可继续。
- Warning：应修复；允许登记后续项，但必须在报告中说明理由。
- Nit：可选，不得用来淹没高优先级发现。

评审结论只能是通过、有条件通过、不通过；有条件通过必须写清条件、责任人与期限。

## 复审与失效

- 修复后必须复审；复审覆盖变更面与受影响发现，并确认没有引入新问题。
- 契约、范围或依赖方向变化时，按实际影响扩大复审；只有影响整个评审对象时才完整复审。
- 来源变化只使受影响结论失效，单纯 HEAD、证据或生命周期记录变化不自动作废其他有效结果。
- 局部失败或材料缺口先诊断，只补受影响部分并保留失败事实；非语义性更正可说明，不迫使重建整套证据。达到既定验收与交付边界即停止，不递归证明证据。
- 不允许用聊天记录、口头确认或“已知悉”替代复审记录。

## 记录

评审报告按固定章节留存，包含结论、范围与输入、发现清单、文档同步检查、简化门、未覆盖项与复审建议。报告与证据一起交接，不能只留一句“评审通过”。
