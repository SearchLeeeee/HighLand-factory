# Block：启动核心

> 类型：项目级通用约束 · 适用：所有 owner profile、feature profile 与四角色子代理
> 冲突处理：与任务指令冲突时先停止并升级，不得静默取舍。

## 目的

保证任何子代理在动手前拥有同一套事实基线，避免“凭印象开工”。

## 规则

1. 按项目规定顺序读完权威文档、工程事实、流程与当前 profile；不得跳读，也不得只读自己关心的部分。
2. 阅读完成后先输出启动摘要，说明自己理解的范围、依据与不确定点。
3. 未确认权威来源前不得修改任何文件，也不得创建“临时权威”文档。
4. 文档缺失、互相矛盾或明显过期时，停止并报告，不得自行补写项目事实。
5. 只加载任务需要的上下文；不要把整库读入却不使用。
6. 发现任务超出当前 profile 的职责或写入范围时，立即停止并转交。
7. 启动阶段不产生代码、配置、迁移或提交。

## 启动摘要最小字段

- 任务与验收目标；
- 权威来源清单（文档与代码位置）；
- 适用的约束块；
- 明确不在范围内的内容；
- 风险与待确认问题；
- 下一步计划与预计影响文件。

## 自检

- [ ] 能指出每份必读文档的作用，而不是只报文件名。
- [ ] 能说出自己的写入边界与升级路径。
- [ ] 不确定点已列出，而不是替项目做决定。
