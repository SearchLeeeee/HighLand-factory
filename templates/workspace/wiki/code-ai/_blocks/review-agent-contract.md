# Block：评审 Agent 契约

> 类型：项目级通用约束 · 适用：所有独立评审角色
> 本块规定报告契约；评审程序与发现级别以项目评审入口页为准。

## 固定报告章节

评审报告必须包含以下章节，顺序固定，缺项写“无”，不得改名或合并：

```markdown
## 评审结论
## 评审范围与输入
## 发现清单
### Blocker
### High
### Warning
### Nit
## 文档同步检查
## 简化门
## 未覆盖项与残余风险
## 复审建议
```

## 各章节最低要求

- **评审结论**：只能是“通过 / 有条件通过 / 不通过”，一句说明理由；有条件通过列出条件、责任人与期限。
- **评审范围与输入**：评审对象、基线、文件或模块范围、采信的权威来源；缺项要写清缺失。
- **发现清单**：每条发现包含编号、位置、证据、影响与建议；按级别归入对应子章节。
- **文档同步检查**：列出应同步的文档与结论（已同步 / 未同步 / 不需要），未同步说明影响级别。
- **简化门**：回答是否存在更小的正确实现；有则给出具体建议，无则写“未发现可简化项”。
- **未覆盖项与残余风险**：明确未检查的内容、环境差异与需要后续跟踪的事项。
- **复审建议**：需要复审的范围、触发条件与建议轮次。

## 写作约束

1. 先结论后证据；读者不读细节也能判断是否阻断。
2. 每条发现都必须可定位、可复现；没有证据的疑虑只能作为待查项。
3. 不得用“整体感觉”“大概率”替代判断；不得因实现者解释而删除已证实的问题。
4. 不得直接修改被评审对象；不得代替实现角色写代码。
5. 不得泄露凭据、个人数据或生产信息。
6. 报告与结论只对当次基线有效；基线变化需重新评审。

## 自检

- [ ] 九个固定章节齐全，顺序正确。
- [ ] 结论与发现级别自洽，没有“不通过但无 Blocker/High”的矛盾。
- [ ] 每条发现都有位置与证据。
- [ ] 未覆盖项没有被隐藏。
- [ ] 有条件通过的条件可执行、有人负责、有期限。
