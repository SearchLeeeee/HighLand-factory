# Block：通用完成定义

> 类型：项目级通用约束 · 适用：所有任务与所有 owner

## 完成的标准

一个任务只有同时满足以下条件才算完成，缺一项即为“未完成”：

1. 验收标准逐条满足，并有可复现证据。
2. 新增或改变的行为有对应层级的测试；修复缺陷有回归用例。
3. 失败路径、边界条件与错误信息经过检查，不是只验证主路径。
4. 受影响的文档、工程事实、README 导航已同步。
5. 达到评审条件的工作已通过独立评审，发现已处置或登记。
6. 没有引入真实凭据、敏感数据、生产地址或调试残留。
7. 变更范围最小，没有夹带无关重构或格式化。
8. 高风险操作有回滚方案，且回滚方式被验证或至少被推演。
9. 交接文档完整，后续角色无需猜测上下文。
10. 只有获得授权时才执行提交与推送；未授权时明确停在“变更就绪”。

## 不算完成的情形

- 测试没跑或只跑了部分，却声称通过；
- 文档“稍后补”，或只在口头说明里更新；
- 把 Blocker/High 降级为后续项却没有 owner 书面接受；
- 用临时脚本、手工操作或本地环境绕过可复现流程；
- 代码能跑但错误路径、权限或数据边界未检查；
- 只改了自己关心的部分，留下孤儿文件或死链；
- 提交里混入无关改动，无法独立审阅。

## 关闭前自检

- [ ] 验收项与证据一一对应。
- [ ] 测试真实执行过，失败路径有覆盖。
- [ ] 文档同步与导航可达性已检查。
- [ ] 评审结论明确，遗留项有责任人与期限。
- [ ] 工作区干净，提交粒度符合当前仓库模式。
- [ ] 交接写明未覆盖项与残余风险。

## 与项目规则的关系

本块给通用下限；项目可以加严（例如增加性能、安全或合规门），但不得以减少步骤为由放宽上述条件。
