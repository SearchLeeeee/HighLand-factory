# Block：测试与质量门

> 类型：项目级通用约束 · 适用：所有实现与验证

## 分层原则

- 单元层：纯逻辑、边界与错误分支，快速、确定、可并行。
- 集成层：模块契约、数据访问、序列化、事务与失败重试。
- 端到端或验收层：真实用户路径与不可逆操作的保护。
- 回归层：历史缺陷的固定用例，防止再次发生。

测试放在能最直接证明该行为的层级，不用端到端测试替代单元测试，也不用单元测试假装覆盖了集成契约。

## 必须满足

1. 新增行为必须有测试；修复缺陷必须先补能复现问题的回归用例。
2. 覆盖失败路径：非法输入、依赖失败、超时、部分成功、权限拒绝。
3. 测试确定性：不依赖真实时间、随机数、网络或执行顺序；必须控制时使用可注入的时钟、种子或假实现。
4. 测试必须能因正确原因失败：确认在未修复时确实红，再确认修复后绿。
5. 不为了测试在生产代码中加入绕过分支、特权后门或仅测试可见的状态。
6. 测试数据与夹具符合治理要求，不包含真实敏感数据。
7. 测试输出与日志不得泄露凭据或个人信息。

## 质量判断

- 覆盖率是信号不是目标；未覆盖的关键分支比总覆盖率更重要。
- 不稳定的测试不得直接删除；应隔离、登记责任人并限期修复。
- 跳过或禁用测试必须在变更中说明原因、范围与恢复条件。
- 性能、并发、安全或兼容性风险相关变更，需要有对应类型的验证，而不只是功能测试。
- 测试通过但证据不可复现，视为未验证。

## 交付前自检

- [ ] 新行为与缺陷修复都有测试。
- [ ] 失败路径至少覆盖主要分支。
- [ ] 测试可重复执行，不依赖本机状态。
- [ ] 没有测试专用后门或敏感数据。
- [ ] 跳过项已登记并有恢复计划。
- [ ] 验证交接中的证据可被他人复现。
