# Block：测试与质量门

> 类型：项目级通用约束 · 适用：所有实现与验证

## 分层原则

- 单元层：纯逻辑、边界与错误分支，快速、确定、可并行。
- 集成层：模块契约、数据访问、序列化、事务与失败重试。
- 端到端或验收层：真实用户路径与不可逆操作的保护。
- 回归层：历史缺陷的固定用例，防止再次发生。

测试放在能最直接证明该行为的层级，不用端到端测试替代单元测试，也不用单元测试假装覆盖了集成契约。默认采用最小充分检查集合，范围依据实际改动及其影响；同一事实不叠加等价校验，复用未变化且仍适用的结果。独立验证保持独立判断，不默认重跑全部检查或重建环境；主编排核对关键证据并按实际风险抽查。

执行前从项目配置、锁定依赖和正式验收条件确定最小环境预检，优先使用轻量只读检查；确需临时文件或进程探针时，只在任务拥有且获准的范围内进行。复用适用的工具链、缓存、制品和健康环境，由一个指定角色补齐缺失前提，不因验收角色切换重复准备。

复用须保留来源、配置和状态隔离条件；相关输入改变时只重做受影响部分，同对象、制品、会话或连续操作要求不能被拆散。环境失败先定位执行阶段与原因，保留失败事实，不重复启动或盲目重跑同一命令。具体做法从 `.factory/local.yaml` 的 `factory_root` 解析 `skills/hl-workflow-governance/references/execution-preparation.md`；结果放现有计划和交接中，不新增检查报表或审批。

复用或接续的证据须能从正式记录定位实际来源、必要对象/版本/run 身份和可访问入口，并明确证明范围及未执行、未证或阻塞的必需项。读取资料不等于独立接纳证据。来源变化时保留旧事实，记录原因、旧新来源、连续性影响及受影响项，同步同一计划与验收结果；其他有效结论保留，不增加例行确认。

## 必须满足

1. 新增行为必须有测试；修复缺陷必须先补能复现问题的回归用例。
2. 覆盖与当前行为和风险有关的失败路径，例如非法输入、依赖失败、超时、部分成功、权限拒绝。
3. 测试确定性：不依赖真实时间、随机数、网络或执行顺序；必须控制时使用可注入的时钟、种子或假实现。
4. 测试必须能因正确原因失败：确认在未修复时确实红，再确认修复后绿。
5. 不为了测试在生产代码中加入绕过分支、特权后门或仅测试可见的状态。
6. 测试数据与夹具符合治理要求，不包含真实敏感数据。
7. 测试输出与日志不得泄露凭据或个人信息。

## 质量判断

- 覆盖率是信号不是目标；未覆盖的关键分支比总覆盖率更重要。
- 不稳定的测试不得直接删除；应隔离、登记责任人并限期修复。
- 跳过或禁用测试必须在变更中说明原因、范围与恢复条件。
- 性能、并发、安全或兼容性风险相关变更，需要有对应类型的验证，而不只是功能测试。
- 测试通过但证据不可复现，对应验收项视为未验证；先诊断并补齐受影响部分，不自动作废其他有效结果或重做整个 run。
- 新建场景通过只能支持它实际覆盖的能力；同标签、同 ID 或同代码不证明原状态链延续。仅当原验收允许且有实际数据沿袭依据时，新实例才可满足相应接续条件；缺失的原链路证明保持未验证，不以能力通过覆盖。
- 保留必要的执行结果与失败记录，产生原始日志时与可清理的测试 output 分开保存，保留失败和未执行事实，不默认对日志或全部证据计算摘要；非语义性格式或文字更正可说明，不迫使重建整套证据。
- 对象身份、来源变化及额外隔离的适用条件统一见[评审门](review-gate.md)；验证按同一来源边界判断受影响结果。
- 满足既定验收和交付边界即停止，不递归为证据补做整套证明；明确要求的截图等验收仍须真实执行。

## 交付前自检

- [ ] 新行为与缺陷修复都有测试。
- [ ] 失败路径至少覆盖主要分支。
- [ ] 测试可重复执行，不依赖本机状态。
- [ ] 没有测试专用后门或敏感数据。
- [ ] 跳过项已登记并有恢复计划。
- [ ] 验证交接中的证据可被他人复现。
