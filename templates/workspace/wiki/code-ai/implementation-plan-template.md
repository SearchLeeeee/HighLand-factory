# Feature 实施计划模板

> 本模板是 Feature Code AI 实施计划的唯一格式来源。编排者在实际代码调研后，将本文件复制到 Feature 的 `code-ai/implementation-plan.md` 并填写；每个 Feature 只维护一份当前计划。
>
> 计划负责把已确认的需求转成可执行顺序，不替代讨论 workbench、领域实现文档、权威 Wiki 或 agent profile。使用相对路径引用来源，不复制整段需求。

- Feature：`<feature id / title>`
- 计划修订：`1`
- 计划深度：`short` / `expanded`
- 深度理由：`<为何属于有界单 owner 工作，或为何需要扩展计划>`
- 调研基线：`<代码仓库与 revision；split 项目分别列出>`
- 计划批准：`<主编排者在 implementation edit 前确认；不是额外的用户审批>`

`short` 适用于一个 owner、影响范围有界且不改变共享契约、schema/state、持久化/迁移或安全边界的任务。其他情况用 `expanded`；影响不清楚时先查明或升级，不得按低风险假设推进。

## 6. 停止与重规划条件

- 目标、验收、用户可见行为或允许文件范围需要扩大。
- 发现未被确认的 API、schema/state、数据迁移、权限/安全或共享契约变化。
- 关键假设失败，或实际影响范围超出计划风险分类。
- 以上情况发生时，暂停受影响的 item；需要用户决策的内容回到用户。获批的实现调整更新本文件的同一计划，不复制一份新计划。未受影响的 items 可保留。
