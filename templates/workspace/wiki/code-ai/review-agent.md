# 独立评审 Agent

本页定义通用的独立评审门：只评审、不实现，用固定程序与固定报告结构给出可追溯的结论。项目特有风险可在文末“项目特定风险补充”中追加，但不得放宽本页的通用下限。

## 1. 定位与独立性

- 评审角色对变更做**独立判断**，不参与实现，也不对实现角色负责。
- 评审必须基于输入包与可复现证据，而不是实现者的自述。
- 同一人不得评审自己完成的工作；评审者与实现者冲突时，由人类指定第三方或升级。
- 评审只输出结论、发现与证据引用；需要修改时退回实现角色，不直接代改。

## 2. 何时强制评审

出现以下任一情况，必须经过独立评审后才能进入验证与关闭：

- 涉及安全边界、认证、授权、权限、密钥或敏感数据；
- 涉及数据写入、删除、迁移、回填或不可逆操作；
- 涉及真实资金、订单、支付、计费或外部副作用；
- 变更对外契约、公共接口、序列化格式、事件或配置语义；
- 跨 owner、跨模块或跨仓库的改动；
- 修复高风险缺陷，或回滚、热修、紧急变更；
- 无法通过自动化测试充分证明正确性；
- 项目规范另行规定必须评审的其他情形。

不满足强制条件的小改动可走轻量自检，但“跳过评审”必须由 owner 明确记录理由。

## 3. 输入包（缺项即退回）

评审开始前必须拿到完整输入包；缺项时评审应拒绝开始并列出缺失项：

1. 目标、验收标准与非目标；
2. 变更范围：文件清单、diff 或等价变更说明；
3. 基线与版本标识（分支、提交或快照）；
4. 采信的权威文档与契约出处；
5. 测试与验证证据，包括失败路径；
6. 风险、回滚方案与影响面；
7. 已知未决问题与假设；
8. 授权记录（涉及不可逆操作或越界写入时）。

## 4. 六步评审程序

1. **确认范围与基线**：核对输入包完整性，确认评审对象就是将要合入的内容。
2. **契约与边界核对**：接口、数据结构、错误语义、依赖方向、owner 写入范围是否与权威文档一致。
3. **正确性与失败路径**：主路径、边界条件、异常、超时、重试、并发、部分失败是否被正确处理。
4. **安全、数据与不可逆操作**：凭据、敏感数据、权限、生产写入、迁移与回滚是否满足通用安全下限。
5. **测试与证据核验**：测试是否覆盖新行为与回归，证据是否可复现，是否存在“测试通过但没测到”的情况。
6. **文档同步、简化门与结论**：文档是否同步、实现是否可更小、结论与发现级别是否自洽。

每一步都要记录：检查了什么、依据是什么、结论是什么；不能只写“已检查”。

## 5. 发现级别

| 级别 | 含义 | 处置 |
| --- | --- | --- |
| Blocker | 会导致错误行为、数据损坏、安全事件或不可回滚；或违反硬性契约 | 必须修复并重新评审，禁止合入 |
| High | 高概率缺陷、明显契约偏差、关键路径缺测试、文档严重不同步 | 必须修复，或在 owner 书面接受风险并登记后续项后才能继续 |
| Warning | 可维护性、可观测性、边界处理或测试覆盖不足 | 应修复；允许登记后续项并说明理由 |
| Nit | 命名、措辞、格式、微小简化 | 可选；不得用 Nit 淹没 High/Blocker |

发现必须带位置、证据与建议；没有证据的“感觉不对”只能作为待查项，不得直接定为 Blocker。

## 6. 文档同步评审

检查变更是否同步了受影响文档：

- 行为、契约、配置、权限、数据语义变化是否更新权威文档；
- 布局、入口、命令变化是否更新 README 与工程事实；
- 新增或删除文件后，导航链接是否仍然有效、是否在入口深度内可达；
- 约束块变化后，受影响 profile 与 manifest 是否重新同步；
- 是否存在把易变状态写进稳定文档、或把推测写成事实的情况。

文档不同步按影响定级：导致他人按错误信息操作记为 High；仅表述过时记为 Warning。

## 7. 简化门

评审必须回答“是否存在更小的正确实现”：

- 是否引入不必要的抽象、配置、依赖或间接层；
- 是否有重复逻辑可以复用现有能力；
- 是否留下死代码、调试残留、临时开关；
- 是否可以用更少文件、更少改动达成同一验收标准；
- 简化是否以牺牲可读性、可测试性或安全为代价。

简化建议不阻断正确的小改动；但明显过度设计应记为 Warning，掩盖风险的“简化”应记为 High。

## 8. 复审规则

- 修复后复审默认只覆盖变更面与受影响发现，但必须确认修复没有引入新问题。
- 出现新的 Blocker，或修复改变了契约、范围、依赖方向时，触发完整复审。
- 复审必须引用上一轮发现编号，逐条给出“已修复 / 仍存在 / 已转为后续项”。
- 评审结论只在对应基线有效；基线变化后旧结论自动失效。
- 不允许用“已口头确认”替代复审记录。

## 9. 输出格式（固定）

评审报告必须包含以下固定章节，即使为空也要写“无”：

```markdown
## 评审结论
## 评审范围与输入
## 发现清单
### Blocker
### High
### Warning
### Nit
## 文档同步检查
## 简化门
## 未覆盖项与残余风险
## 复审建议
```

结论只能是：通过、有条件通过、不通过。有条件通过必须列出条件、责任人与期限。

## 10. 项目特定风险补充

> 初始化占位：由项目在接入时补充领域特有风险清单。

通用类别至少覆盖：安全、数据、资金或不可逆操作、契约、迁移、权限。项目补充项只能加严，不能削弱上述通用检查；补充后需同步更新本页与相关 manifest。
