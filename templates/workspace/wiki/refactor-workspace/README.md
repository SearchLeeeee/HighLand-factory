# Refactor Workspace

本目录保存用户手动发起的扫描与重构记录。`hl-refactor` 负责建立运行记录，记录范围、
候选证据、收益与完整成本、用户选择、实施结果、评审和验证；无问题时允许零改动结束。

## 与当前态 Wiki 的边界

- 本目录记录一次维护过程，不是当前系统功能或业务场景的权威。
- 默认排除在当前态语义扫描、长期知识发现、MOC 导航、可达性门禁和自动补链之外。
- 只有该次重构、显式交接或审计点名记录时才定向读取；长期文档更新应落在现有权威位置。
- 隔离规则由 factory 的统一过程区解析器定义；额外过程区在项目配置
  `workflow.process_workspaces` 中显式登记，不按文件夹名称猜测。

## 维护约束

- 仅在全部 Initiative 已完成时受理。每个实施单元复核生命周期、来源及选定文件范围；
  出现新的需求活动或来源变化时重新判断受影响范围。
- 先只读扫描，按证据说明收益、成本与风险；用户选择候选后才开始相应实施。
- 不创建第二套 Initiative 生命周期，不重开已完成需求，也不改写其历史结论。
- 流程治理建议记录并告知用户，由用户在另一个会话决定修改。
- 无需预先创建空运行目录；具体运行记录由 Skill 按需生成。
